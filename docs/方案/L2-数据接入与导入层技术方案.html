L2 · INGESTION & IMPORT

数据接入与导入层技术方案

实现标准文件、人工提交与系统接口接入，将来源数据解析为可追溯的规范化候选记录；负责接收与语法层检查，不承担法规规则判断和护照发布。

Draft 0.1Java 17 · Spring Boot 3/api/v1

1. 范围与模块边界

模块：passport-ingest，MVP 在 Spring Boot 模块化单体中运行；后台 worker 异步消费导入任务。未来流量/隔离需求明确后再独立部署，不在首期拆微服务。

输入：L1 版本化 CSV/XLSX/JSON 模板、合作方 API、文件及 source metadata。输出：canonical import record、导入结果和事件给 L3/L4。

本层职责：鉴权、文件接收、病毒扫描、解析、基础类型/列结构检查、幂等导入任务、行错误报告、可靠事件发布。不负责：法规字段必填/合规资格（L4）、电池主数据持久化（L3）、生成护照（L5）。

全局约定：ID 使用 UUID 字符串；时间 UTC ISO-8601；请求必须携带 Idempotency-Key（文件上传）或来源记录键；统一错误体见架构文档 Shared Contract；事件统一 envelope，topic 以 bp. 开头。

4. 状态机与处理流程

CREATED → UPLOADED → SCANNING → PARSING → VALIDATING → PUBLISHING → COMPLETED | PARTIAL | FAILED；安全扫描拒绝为 REJECTED。允许 CREATED/FAILED/RETRYABLE_PARTIAL 经显式操作重试。每次执行增加 attempt_no，不覆盖既有错误审计。

  1. 校验租户、source system、模板版本与文件名/大小/扩展名；MIME 通过内容嗅探判定。
  2. 先传私有 OSS 隔离区，状态 SCANNING；ClamAV/等效扫描结果为 clean 后才解析。
  3. 限制压缩展开比、单元格长度、工作表数；拒绝宏、外链公式、嵌套压缩和非预期格式。
  4. 按流解析，验证 header/schema、必需列、数据类型/枚举和源级幂等键；这一步不运行 L4 规则。
  5. 逐批 500 行写入 staging records；事务提交后通过 outbox/RocketMQ 发事件给 L3/L4。拒绝行写 row_error，可重放无错误行。
  6. 完成 job 统计与审计，错误报告用 CSV 中性化以防公式注入。

5. MySQL 8 存储模型

CREATE TABLE bp_import_job (
  id CHAR(36) PRIMARY KEY, org_id CHAR(36) NOT NULL,
  source_system VARCHAR(64) NOT NULL, entity_type VARCHAR(40) NOT NULL,
  schema_version VARCHAR(32) NOT NULL, status VARCHAR(20) NOT NULL,
  object_key VARCHAR(512) NOT NULL, file_sha256 CHAR(64) NOT NULL,
  total_rows INT NOT NULL DEFAULT 0, accepted_rows INT NOT NULL DEFAULT 0,
  rejected_rows INT NOT NULL DEFAULT 0, attempt_no INT NOT NULL DEFAULT 0,
  created_by CHAR(36) NOT NULL, created_at DATETIME(3) NOT NULL,
  updated_at DATETIME(3) NOT NULL, version BIGINT NOT NULL DEFAULT 0,
  UNIQUE KEY uk_org_idempotency (org_id, id),
  KEY idx_org_status_created (org_id,status,created_at),
  KEY idx_org_sha (org_id,file_sha256)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE bp_import_row_error (
  id BIGINT AUTO_INCREMENT PRIMARY KEY, org_id CHAR(36) NOT NULL,
  job_id CHAR(36) NOT NULL, row_no INT NOT NULL,
  field_code VARCHAR(100), error_code VARCHAR(80) NOT NULL,
  safe_message VARCHAR(500) NOT NULL, raw_value_hash CHAR(64),
  created_at DATETIME(3) NOT NULL,
  UNIQUE KEY uk_org_job_row_field_code (org_id,job_id,row_no,field_code,error_code),
  KEY idx_org_job (org_id,job_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

生产 DDL 增加 FK（同租户约束在应用/复合键实现）、作业审计及配置迁移。文件名和原始敏感值不写日志；大文件错误报告放私有 OSS，短时签名 URL 下载。

对象路径：tenant/{orgId}/imports/{yyyy}/{MM}/{jobId}/source；隔离文件扫描完成后按保留策略转移或删除。

6. 事件、错误、可靠性

输入：bp.ingest.record.v1；完成：bp.ingest.completed.v1。Envelope 字段：eventId,eventType,eventVersion,occurredAt,orgId,traceId,producer,payload。payload 至少包含 jobId、entityType、schemaVersion、sourceSystem、sourceRecordId、recordHash、canonicalData；不包含原始证据附件内容。

  • RocketMQ 至少一次投递，消费者以 eventId + orgId 去重；消息消费成功后才 ACK。
  • 事务 outbox 与 job/staging 状态同库提交；发布失败指数退避，最大 8 次后 DLQ；提供按 jobId 重放运维入口。
  • 文件 sha256 用于重复提示而非全局拒收；显式 Idempotency-Key 唯一作用域为 org_id。
  • 失败重试不重新扫描 clean 的不可变文件；病毒扫描状态不可绕过。
  • 日志使用 traceId/jobId/orgId/sourceSystem，不打印 token、原始个人信息、文件内容。

7. 安全与权限

  • OIDC JWT 验签由 Spring Security Resource Server 完成；组织上下文只信任已签名 claim，不接受客户端 body 中的 orgId 覆盖。
  • 伙伴客户端 scopes 按 source system 限定 entityType/字段范围；工作台用户按 org_id 行级隔离。
  • 所有 Mapper 查询显式携带 org_id；MyBatis 租户插件只是纵深防御，不作为唯一控制。
  • 防止 ZIP bomb、XXE、CSV/Excel 公式执行、路径穿越、MIME 伪装、越权附件下载。
  • 审计上传、扫描结果、重试、错误报告下载、伙伴 API 调用；敏感证据走私有 OSS 和短 TTL 签名地址。

8. 测试与开发任务

验收测试

  1. 20MB/50k 行上限生效；超限响应明确且服务不 OOM。
  2. 合法 CSV/XLSX 分块解析；损坏、宏、压缩炸弹、公式、伪装 MIME 文件被安全拒绝。
  3. 重复提交同幂等键不重复产生记录；不同内容冲突返回 409。
  4. 行级错误报告行号/字段准确，CSV 导出对以 =,+,-,@ 起始内容做中性化。
  5. 异步任务可恢复；重复 MQ 消息不重复写入；DLQ 可审计重放。
  6. 跨租户 jobId、OSS key、错误报告访问均返回统一 404/拒绝。

开发任务

  1. 接口 DTO、OIDC scopes、错误 envelope 和 OpenAPI。
  2. ImportJob/RowError DDL、Mapper、状态机与幂等。
  3. 私有 OSS、病毒扫描适配器及上传限制。
  4. CSV/XLSX 流解析、schema 校验和错误报告。
  5. Outbox/MQ 事件、retry/DLQ、指标与告警。
  6. 集成测试及 L1/L3/L4 联调。

9. 可运行原型：统一管理台与单体后端

本仓库将 L1 数据源登记与 L2 CSV 导入作为同一管理台中的两个分层页面，由单一 Spring Boot 应用承载；不是两个独立前后端服务。代码仍保留 L1、L2 包边界，接口分别使用 /api/v1/l1/** 与 /api/v1/l2/**。

  • 唯一后端：l1-cloud-data，Java 17 / Spring Boot 3 / H2，端口 8080。L2 进程内查询 L1 数据源，不通过 HTTP 自调用。
  • 唯一前端：l1-web，React 18 / Vite / Ant Design 5，端口 5174。侧栏切换“数据源登记”和“导入任务”；Vite 将 /api 请求代理到 8080。
  • 运行：先在 l1-cloud-data 执行 mvn spring-boot:run，再在 l1-web 执行 npm install && npm run dev，打开 http://localhost:5174。
  • 原型只支持三类 CSV 模板，最大 20 MB / 50,000 行；任务、staging 记录与源文件存放在后端工作目录的 data/ 下。
原型边界：病毒扫描结果模拟为 clean；租户隔离通过 X-Org-Code 演示头实现，不是身份认证或生产级授权；数据保存在本地 H2 与磁盘，不提供 ClamAV、对象存储、OIDC/RBAC、MQ/outbox、L3 发布或生产级恢复保证。L2 执行语法/结构校验，不代表法规合规结论。

验证：在 l1-cloud-data 执行 mvn test；在 l1-web 执行 npm run build && npm test。
