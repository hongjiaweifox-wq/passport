L1 · BATTERY PASSPORT DATA SOURCES

数据源与接入规范

定义谁提供什么数据、交付格式与质量责任，供 L2 导入和 L3/L4 消费。本层是数据契约与接入规则，不是运行时微服务。

Draft 0.1适用：欧盟电池护照数据契约：dpp-schema/1.0

1. 范围、职责与边界

负责：数据源登记、责任人、标准数据模板、标识约定、数据交付频率与接入验收规范。

不负责：文件上传处理（L2）、平台持久化（L3）、法规校验与审核（L4）、护照发布/公开访问（L5/L6）。本规范中的质量检查仅限源数据格式和基础自检，不取代法规审查。

输入：制造商/供应链、品牌系统、测试与合规文件、Tuya IoT/BMS、服务与回收伙伴。
输出：符合本页模板的 CSV/XLSX/JSON 交付物、字段来源及证明材料。

关联：架构总览 · L2 接入导入 · L3 结构化数据

3. 全局数据约定

标识

平台主键采用 UUID（字符串形式）；外部记录以 source_system + source_record_id 幂等识别。电池唯一标识按 issuer_code + normalized_sn 唯一；SN 可直接使用，但保留命名空间。二维码公开码与 SN 分离。

时间/单位

时间使用 ISO-8601 UTC，如 2026-11-10T08:30:00Z；日期 YYYY-MM-DD。容量统一 kWh，电压 V，重量 kg；不可静默换算或丢失原始单位。

Schema

每次交付声明 schemaVersion=dpp-schema/1.0。新增可选字段向后兼容；字段语义/单位/枚举改变必须升版本。

文件/附件

仅提交文件引用或上传内容，不在 CSV 单元格中嵌入二进制。源系统/业务编号不得作为平台主键。

4. 标准导入模板（CSV UTF-8）

首期按三类模板拆分；下载文件名和首行字段名均为中文，方便业务填写。系统按列位置映射到稳定的英文内部字段码，历史英文表头仍兼容。所有模板包含模板版本、来源系统、来源记录编号、组织编码。CSV 使用 UTF-8（含 BOM 以兼容表格软件），首行字段名，不允许合并单元格；数值不带千分位符，十进制点使用“.”。

4.1 电池型号模板.csv（型号/修订数据）

字段类型/必填约束示例
model_codestring 必填来源组织内唯一，长度 1–64HOME-BAT-5K
revision_codestring 必填型号修订标识R02
manufacturer_namestring 必填与责任主体登记一致Example Energy GmbH
battery_categoryenum 必填PORTABLE/LMT/EV/INDUSTRIAL/SLIINDUSTRIAL
chemistrystring 必填受控枚举/字典代码LFP
rated_capacity_kwhdecimal 必填>0；定义为电池额定容量5.12
rated_voltage_vdecimal 可选>051.2
market_codestring 必填ISO 国家码或 EUEU
effective_fromdate 必填ISO 日期2026-01-01
source_record_idstring 必填源端可重试稳定值PLM-88412-R02

4.2 电池单体模板.csv（单体/电池序列）

中文表头依次对应内部字段：model_code,revision_code,batch_code,sn,manufactured_at,device_id,source_record_id

sn 为电池铭牌 SN，按签约的 issuer_code 命名空间查重；device_id 可空，设备尚未激活不妨碍电池单体入档。制造时间为 ISO-8601 UTC。

4.3 生命周期事件模板.csv（生命周期事件）

中文表头依次对应内部字段：sn,event_type,event_time,actor_org_code,reason_code,source_record_id,evidence_ref

event_type：COMMISSIONED、REPAIRED、REPLACED、REPURPOSED、REMANUFACTURED、RECYCLED；新增类型由 schema 版本管理。事件必须指向确定电池 SN，证据引用按权限访问。

5. 标识、交付与质量规则

  1. 接入前登记组织、源系统代码、数据 owner、联系人、用途及允许字段；一个来源组织可有多个 source_system。
  2. SN 原值保留；查重键对前后空白做 trim、Unicode NFC 规范化，大小写是否敏感由制造商规则登记；禁止未经业务确认自行去前导零或删除字符。
  3. 幂等键为 org_id + source_system + source_record_id + entity_type；相同键、相同 payload hash 为重复成功；相同键、不同 hash 返回冲突并要求显式新版本/更正。
  4. 字段源头值、来源文件、导入批次、导入时间、提交者需可追溯；修订数据不得静默覆盖已发布版本。
  5. 文件中的公式、宏、外部链接不作为可信数据；扫描及解析规则由 L2 执行，失败行需给出行号和字段码。

6. 安全与交付方式

  • 人工工作台使用 OIDC 登录；系统对系统优先 OAuth2 Client Credentials，短期 token、最小 scopes；签名 webhook 需含时间戳与 nonce 防重放。
  • OSS 证据文件须私有存储，由平台返回短时签名链接；禁止在模板中填公开 URL 或访问令牌。
  • 试点阶段约定工作时间内一个工作日响应数据问题；正式 SLA、吞吐量和保留期限由业务合同及 NFR 决策，不在本规范擅自承诺。
  • 涉及个人信息/家庭设备位置的数据源，默认不纳入公开护照字段；上送前由隐私负责人确认合法依据和最小化范围。

7. 接入验收与开发任务

验收清单

  • 模板下载文件与本页字段版本一致；合法样例可导入，非法枚举、缺必填、错误单位可定位到行/列。
  • 同一 source_record_id 重试不产生重复实体；内容变更能触发冲突或显式修订路径。
  • SN 归一化符合登记规则；跨组织或 issuer 命名空间冲突有明确错误，不错误合并电池。
  • 证据附件访问需鉴权，下载链接限时有效。

实现任务顺序

  1. 维护 schema/字段目录和三类模板样例。
  2. 实现来源登记及组织/source system 管理。
  3. 实现模板版本下载、样例数据校验和源系统 onboarding 指引。
  4. 与 L2 联调导入任务/错误报告；与 L3/L4 联调标识、模型及字段元数据。

8. 可运行原型：前端与数据云端

本仓库提供统一管理台 l1-web（React/TypeScript），以及同时承载 L1 数据源 API 与 L2 导入 API 的单体后端 l1-cloud-data（Spring Boot）。管理台侧栏可在数据源登记与导入任务间切换，首版覆盖数据源列表、检索筛选、新增/编辑、详情、启停、模板下载，以及 CSV 上传、解析、任务追踪和行级错误查看。

后端模块

Java 17、Spring Boot 3、Spring Data JPA；开发数据保存到 H2 文件库 l1-cloud-data/data/l1-passport（相对后端工作目录）。

cd l1-cloud-data
mvn spring-boot:run

前端模块

React 18、Vite、Ant Design 5；Vite 开发服务器使用 5174 端口，并将 /api 代理到本机 8080 后端。

cd l1-web
npm install
npm run dev

打开 http://localhost:5174。演示组织默认 DEMO-ORG，通过 X-Org-Code 请求头区分数据范围；这是本地原型隔离方式，不是身份认证或生产级授权。清除本地演示数据时，停止后端后删除 H2 数据文件及对应锁文件。

接口前缀：L1 为 /api/v1/l1，L2 为 /api/v1/l2。后端、前端测试命令分别在 l1-cloud-data 和 l1-web 执行；统一管理台端口为 5174，后端端口为 8080。
