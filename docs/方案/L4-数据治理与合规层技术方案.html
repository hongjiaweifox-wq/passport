数据治理与合规层技术方案

维护字段字典、适用性规则、质量校验与审批门禁，产出可供 L5 发布的已审核数据快照和字段可见性元数据。

Draft 0.1Java 17 · Spring Boot 3规则配置版本化

1. 职责和边界

L4 是字段目录与法规映射的唯一 owner。L1/L2 提供来源字段；L3 存储已映射规范值；L4 负责质量/适用性判定、审核与发布 gate；L5 根据 L4 输出的字段分类生成服务端投影；L6 不自行筛选数据。

本层输出：版本化 Field Dictionary、Applicability Decision、Validation Run/Issues、Review Decision、发布候选数据及字段访问分类。
不做：原始文件解析、主数据存储、最终护照状态/二维码发布、前端显示逻辑。

模块：passport-governance，包 com.tuya.passport.governance。业务审批和护照发布审批分开：普通数据编辑可 owner 保存并审计；影响对外发布/法规声明的变更走 maker-checker。

3. 适用性与规则执行

规则按 rule_set_id + version 生效，输入 battery_category、capacity、market、placed_on_market_at、intended_use 等数据，输出适用法规标签、护照义务判断、规则引用及待确认项。

门槛不得写死在代码：“工业电池容量 > 2 kWh”等规则作为可配置、可生效日期管理的规则；具体电池分类/组合容量口径和当前生效法规由合规负责人确认。系统不得对不确定项默认为合规通过。

一期使用配置表 + 少量类型安全的 Java RuleStrategy，不引入通用 JSON DSL / 任意脚本执行。规则结果状态：PASS / FAIL / REVIEW_REQUIRED / NOT_APPLICABLE；每次运行记录规则版本和输入快照 hash，可复现。

规则执行顺序

  1. 字段字典语法和类型校验 → 适用性规则 → 条件必填/范围校验 → 证据有效期和来源校验 → 访问分类完整性 → 发布门禁。
  2. issue severity 为 ERROR/WARN/INFO；ERROR 阻断审核/发布，WARN 可经理由豁免但审计，INFO 仅提示。
  3. 规则变更创建新版本，不修改历史结果；影响分析列出相关型号/已发布护照，生成待处理清单。

4. 审核工作流与状态

数据准备：DRAFT → VALIDATION_FAILED | READY_FOR_REVIEW → APPROVED | CHANGES_REQUESTED。maker 不得审核自己提交的 publication-impacting change。普通草稿字段编辑无需逐字段双人审核，但每次修改留审计；首次发布、公开字段变化、法规声明变化、规则豁免需 checker 批准。

动作角色结果
提交审核DATA_EDITOR / COMPLIANCE_MAKER冻结提交快照，生成 review task
批准/退回COMPLIANCE_CHECKER批准需 review_reason；退回需 issue 引用
重新校验系统 / editor引用新 validation_run，不更改旧记录
规则豁免COMPLIANCE_CHECKER限定字段/对象/到期日；不可豁免法规强制项，除非法规配置允许

批准只表示治理层数据通过审核；L5 仍拥有护照 DRAFT/PUBLISHED/SUSPENDED 状态机。

6. 数据表（摘要 DDL）

CREATE TABLE bp_field_definition (
 id CHAR(36) PRIMARY KEY, org_id CHAR(36) NOT NULL,
 field_code VARCHAR(100) NOT NULL, value_type VARCHAR(20) NOT NULL,
 unit_code VARCHAR(24), visibility_class VARCHAR(20) NOT NULL,
 schema_version VARCHAR(32) NOT NULL, legal_reference VARCHAR(255),
 definition_json JSON NOT NULL, status VARCHAR(20) NOT NULL,
 created_at DATETIME(3) NOT NULL,
 UNIQUE KEY uk_org_field_schema(org_id,field_code,schema_version)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE bp_validation_run (
 id CHAR(36) PRIMARY KEY, org_id CHAR(36) NOT NULL,
 subject_type VARCHAR(32) NOT NULL, subject_id CHAR(36) NOT NULL,
 rule_set_id VARCHAR(64) NOT NULL, rule_version INT NOT NULL,
 input_hash CHAR(64) NOT NULL, status VARCHAR(24) NOT NULL,
 error_count INT NOT NULL, warning_count INT NOT NULL,
 started_at DATETIME(3) NOT NULL, finished_at DATETIME(3),
 KEY idx_org_subject_created(org_id,subject_type,subject_id,started_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE bp_review_task (
 id CHAR(36) PRIMARY KEY, org_id CHAR(36) NOT NULL,
 subject_type VARCHAR(32) NOT NULL, subject_id CHAR(36) NOT NULL,
 snapshot_hash CHAR(64) NOT NULL, status VARCHAR(24) NOT NULL,
 maker_id CHAR(36) NOT NULL, checker_id CHAR(36), reason VARCHAR(1000),
 created_at DATETIME(3) NOT NULL, decided_at DATETIME(3),
 KEY idx_org_status_created(org_id,status,created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

同批次补齐 rule_set/version、validation_issue、review_action、applicability_result、audit/outbox 表；生产索引包含 org_id，所有读写 tenant-scoped。字段字典可能由平台级组织维护，需明确系统租户/共享字典查询机制，不能把 org_id 置空绕过隔离。

7. 安全、审计和可靠性

  • JWT claims 中的 org_id/roles/scopes 来自 OIDC；服务端校验 org，跨租户统一 404。
  • 字段可见性由 L4 配置、L5 服务端执行；L6 没有过滤权限。字段分类更改须审批并触发公开投影重建/缓存清理。
  • 审计字段定义变更、规则发布、结果豁免、maker-checker 决策、法规快照导出；审计输出共享 append-only sink，不在每层私建审计真相源。
  • 规则版本不可变；评估任务可异步分批执行，失败重试以 validationRunId 幂等。
  • 异常：规则配置不完整、证据失效、法规映射为 provisional 时返回 REVIEW_REQUIRED，不自动 PASS。

8. 测试与开发任务

  1. 规则单元测试覆盖容量边界（2.0000 / 2.0001 kWh）、类别、市场、生效日期；规则版本可回放。
  2. 公开字段投影仅含 PUBLIC allowlist；RESTRICTED/INTERNAL 字段在返回 JSON/异常信息中无泄露。
  3. ERROR 阻断 review；WARN 豁免必须 checker、理由、到期日并有审计。
  4. Maker 与 checker 同人拒绝；并发 decision 幂等且不重复生成审核结果。
  5. 规则版本更新可产生受影响对象清单；历史审核快照 hash 不变化。
