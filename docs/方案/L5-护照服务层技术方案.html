L5 · PASSPORT LIFECYCLE & RESOLUTION

护照服务层技术方案

承接 L4 已审核的候选数据，建立电池护照、不可变版本、唯一身份解析、二维码访问与发布/暂停能力；所有公开投影由服务端按字段白名单生成。

Draft 0.1Java 17 · Spring Boot 3dpp-schema/1.0

1. 服务边界与核心对象

L5 是护照状态和外部访问入口的 owner。来源：L3 电池标识/关系，L4 审核通过快照与 visibility metadata。输出：public resolver、受控 API、JSON 导出、护照状态事件供 L6/CDN 更新。

标识分离：unique_identifier 是法规意义上分配给电池的标识，可采用满足唯一稳定条件的 SN（带 issuer namespace）；public_code 是随机不可枚举的 URL 解析码。数据库内部 passport_id 不放在二维码。二维码只含稳定 HTTPS URL 和 public_code，不含护照字段值。

模块 passport-service；Spring 模块化单体，包 com.tuya.passport.passport。职责不包括法规规则 owner（L4）、前端渲染（L6）、来源数据采集（L2）。

2. 数据快照与发布状态机

一个护照关联一个 unique_identifier 与电池实体；每次发布产生不可变 passport_version。版本由审核通过数据构建，按照 L4 visibility_class 生成 public_json、restricted_json、regulator_json，内部治理 metadata 不进入公共 payload。

状态：DRAFT → PENDING_REVIEW → PUBLISHED → SUSPENDED | SUPERSEDED → ARCHIVED。初次数据审核在 L4；L5 的 PENDING_REVIEW 表示发布命令待 L5 操作/确认，不重复实现另一套业务审核。已发布版本内容不可更新；更正创建新版本并原子切换 current_version。

  1. L4 发布候选有 validation/review 引用与 snapshot hash；L5 校验签名/权限、对象一致及 hash。
  2. 事务创建新版本、更新 current_version、写 outbox；版本 JSON 与 hash 同事务保存。
  3. 发布成功后清理 Redis/CDN 缓存，发布状态事件；失败可安全重试。
  4. 暂停时先数据库状态切为 SUSPENDED，再使缓存失效并使所有公开解析返回统一不可用状态；不得沿用旧缓存公开数据。

4. 存储模型与缓存

CREATE TABLE bp_passport (
 id CHAR(36) PRIMARY KEY, org_id CHAR(36) NOT NULL,
 battery_unit_id CHAR(36) NOT NULL, unique_identifier VARCHAR(192) NOT NULL,
 issuer_code VARCHAR(64) NOT NULL, public_code CHAR(32) NOT NULL,
 status VARCHAR(20) NOT NULL, current_version INT NOT NULL DEFAULT 0,
 created_at DATETIME(3) NOT NULL, updated_at DATETIME(3) NOT NULL,
 UNIQUE KEY uk_org_identifier(org_id,issuer_code,unique_identifier),
 UNIQUE KEY uk_public_code(public_code),
 KEY idx_org_status(org_id,status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE bp_passport_version (
 id CHAR(36) PRIMARY KEY, org_id CHAR(36) NOT NULL,
 passport_id CHAR(36) NOT NULL, version_no INT NOT NULL,
 schema_version VARCHAR(32) NOT NULL, source_snapshot_hash CHAR(64) NOT NULL,
 public_json JSON NOT NULL, restricted_json JSON NOT NULL,
 regulator_json JSON NOT NULL, public_hash CHAR(64) NOT NULL,
 created_at DATETIME(3) NOT NULL, created_by CHAR(36) NOT NULL,
 UNIQUE KEY uk_org_passport_version(org_id,passport_id,version_no),
 KEY idx_org_created(org_id,created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

public_code 使用 CSPRNG 生成至少 128-bit entropy 后 Base64URL/hex 编码（长度 32 hex chars）；碰撞由 UNIQUE 冲突后重试解决。禁止把 SN 编进 URL path。审核通过快照需在快照存储/审计系统可验证来源。

Redis：dpp:public:{publicCode}:{version} → public JSON + ETag；dpp:status:{publicCode} → status/currentVersion。暂停/发布操作写入失效事件，状态缓存短 TTL 并优先检查暂停状态。CDN purge 失败时重试；敏感 projection 禁止 public cache。

5. 权限、审计与防滥用

  • 公开访问无需登录，但匿名仅能得到 public_json allowlist。所有 projection 在 server side 从 L4 分类数据构建；不能让 L6 自行过滤整个 JSON。
  • 受控访问采用 OIDC JWT scopes，组织隔离；监管授权含主体、目的、范围、到期时间、签发人和撤销机制。
  • public_code 不可预测；按 IP、ASN、组织/客户端限流并接 WAF/bot protection；无批量匿名 resolve API。
  • 审计发布/暂停/恢复/版本更正/受控访问/批量导出。受控数据读取审计与操作审计区分；统一送 append-only audit sink。
  • 不缓存受控响应；响应不含内部对象 ID、个人信息、source ref、evidence URL、错误堆栈。
  • 公开页面安全 headers：HSTS、CSP、X-Content-Type-Options、frame-ancestors；CORS 仅允许明确源。

6. 错误处理与一致性

  • 发布命令需 Idempotency-Key；同 snapshot hash 重放返回既有版本，hash 不同返回 409。
  • public_code 生成、护照创建和标识唯一冲突走数据库唯一约束；不可静默覆盖其他 passport。
  • 发布 DB 事务与 outbox 原子提交；CDN purge、事件推送失败异步重试并告警。
  • 缓存故障时读 DB/版本存储降级；数据库不可用时可返回短时已缓存公开数据（仅非暂停状态可保证）；状态缓存设计必须优先避免已暂停护照继续泄露。
  • 暂停/撤回按强一致性路径处理；在 purge 确认前公开解析层短 TTL 并每次确认权威状态。

7. 测试、验收与任务

  1. public/restricted/regulator/internal fixture 投影精确匹配 allowlist；异常消息、导出及 HTML hydration 中无受控字段。
  2. 随机 public_code 无顺序/预测关系；抽样暴力探测有速率限制；未知和无权对象不泄露存在性。
  3. 同一 unique_identifier 重复建护照冲突可定位；SN 仅作为 unique_identifier 时需有 issuer namespace uniqueness test。
  4. 发布版本不可变；同 snapshot 重试幂等；新版本切换原子；并发发布只有一个 current version。
  5. 暂停后数据库、Redis、CDN 路径均验证缓存清理/短 TTL，不能读取旧公开 JSON。
  6. schema dpp-schema/1.0 导出校验；历史版本兼容反序列化。

实现任务：护照实体/DDL → 身份和 public code service → L4 candidate adapter → snapshot projector/hash → 发布状态和 outbox → public resolver/API → restricted authz/export → Redis/CDN invalidation → 安全与 E2E。
