欧盟电池护照

01 · 结论摘要

建议将电池护照建设为“电池产品数据管理 + 唯一身份标识 + 按角色授权的在线护照 + 生命周期更新”的平台能力；先支持电池型号级数据，再支持单体电池运行数据与维修/翻新等生命周期事件。

法规门槛：自 2027 年 2 月 18 日起，投放欧盟市场或投入使用的 LMT 电池、容量 大于 2 kWh 的工业电池及电动汽车电池须有电池护照。家用固定式储能电池通常归入工业电池范畴；本项目应按电池本体及其容量判定，不能只按“家用”或整机商品名称豁免。

产品原则

护照对象是电池，不是逆变器或整套能源设备。阳台光伏一体机/储能系统中，只要含有符合门槛的电池，应为该电池建立护照，并将其与设备、型号及序列号关联。

责任原则

法规责任主体是将电池投放欧盟市场的经济运营者。涂鸦若提供平台或受托服务，不因此自动成为该法定义务主体；需在商业与合规合同中明确数据提供、校验、发布、维护责任。

平台原则

提供公开信息与受控信息分层访问；数据结构化、机器可读、可互操作；二维码解析到电池唯一标识与在线护照页面。

落地原则

优先做法规字段、数据责任人与审核、护照生成、二维码和访问控制；再接入 BMS/设备运行数据及维修、再利用、再制造、回收等生命周期事件。

合规提示：本稿是产品需求基线，不构成法律意见。开发立项前需由欧盟法规/产品合规团队核对法规现行合并文本、届时生效的授权/实施法案、适用标准，以及具体电池配置与经济运营者身份。

02 · 范围与适用性

产品场景初步判断平台处理建议需要核实
阳台光伏一体机（含储能电池）对其中电池单独分类。若为固定式储能工业电池且容量 > 2 kWh，原则上纳入护照要求。建立电池护照实体；关联一体机型号、设备 ID、BMS/电池序列号。整机本身不替代电池护照。电池容量口径、是否可拆分/更换、由谁进口/投放欧盟、产品组合销售方式。
户用固定式储能固定式储能通常按工业电池分析；“用于家庭”本身不构成豁免。容量 > 2 kWh 是该类护照门槛。按电池型号 + 单体电池唯一 ID 管理；若多个电池模块构成系统，明确法规意义上的电池单元边界。系统由多个电池组成时的护照颗粒度、替换模块及扩容配置、型号定义。
≤ 2 kWh 的固定式储能电池不满足 Article 77 对工业电池护照的“> 2 kWh”门槛；仍可能适用其他标签、信息、可持续性或国家要求。可在平台采用统一数据模型，但按合规规则决定是否生成法定护照；不可将“无护照义务”误写为“无任何电池法规义务”。配置组合后的容量认定及其他法规义务。
不含电池的光伏/逆变器设备不因设备是储能相关产品而自动成为电池护照对象。不生成电池护照；可提供设备页与电池护照之间的关联入口。商品 SKU 中是否存在随附、内置或独立销售的电池。
建议的上线筛查字段：电池类别、额定容量（kWh）、化学体系、是否固定式储能、目标市场、首次投放市场日期、经济运营者、是否 LMT/EV。筛查结果应保留规则版本和人工复核记录。

03 · 角色与产品边界

角色主要职责平台权限建议
经济运营者 / 制造商 / 欧盟进口商明确电池适用性；提交并对法规数据负责；批准护照发布并持续维护；确保信息真实、完整、更新。组织/租户管理员、数据责任人、合规审核/发布人；可管理本组织电池和授权供应商。
电池制造商 / ODM / 电芯或模组供应商提供型号、材料、性能、碳足迹、回收含量等源数据及证明文件；配合更正。按字段授权供数；不应默认获得其他客户产品数据访问权。
涂鸦平台提供数据建模、验证、版本、二维码解析、访问控制、审计、导出及集成能力。按委托与数据处理协议运维；平台管理员操作需可审计，默认不作为数据所有者。
终端用户 / 维修商 / 回收商查看公开信息；在法规允许且具备合法利益时访问特定受控数据；产生事件或状态数据。匿名公开访问 + 经身份/资质核验的授权访问；按最小权限提供数据。
公告机构 / 市场监管机构 / 欧盟机构在法定权限范围内访问相关护照信息。机构身份校验、授权范围、访问期限、审计和合规导出。

待决策 法律责任、数据控制者/处理者关系及护照发布主体须在涂鸦、品牌方、制造商、进口商之间确认；平台技术代运营不应被误当作责任转移。

05 · 数据模型与字段基线

建议拆分为“法规字段字典 + 型号档案 + 单体护照 + 生命周期事件 + 证据与权限”。法规附件字段和授权边界需逐项映射至 EU 2023/1542 第 77、78 条及附件 XIII；下表是产品数据域建议，不代表附件 XIII 逐字清单。

数据域建议字段示例颗粒度可见性 / 备注
标识与责任主体护照唯一标识、二维码解析 URL、电池型号、序列号、制造商、经济运营者、生产日期/地点、投放市场日期型号 + 单体依附件 XIII 和适用标签要求映射；公开/受控属性需由合规确认。
分类与组成电池类别、化学体系、额定容量/电压、重量、材料组成、危险物质、关键原材料型号容量统一单位与口径；必要时关联可追溯证据和供应商。
可持续性信息碳足迹及性能等级、回收材料含量、尽职调查相关声明型号 / 生产批次按法规适用日期、计算规则、核验状态配置；不要用估算值替代正式声明。
性能与耐久额定容量、可用容量、功率、能量效率、循环寿命/耐久指标、适用测试条件型号明确定义、测试条件、单位、测试/声明来源及版本。
运行状态SoH、预期寿命、循环/使用状态、维修更换记录（按法规及授权范围）单体 / 事件区分设备遥测与制造商声明；遵循数据最小化、授权、质量和留存策略。
维修与循环利用维修/替换、翻新、再用途转换、再制造、拆解、回收事件及执行组织单体 / 事件法规要求或特定合法利益所需时按角色开放；记录事件时间、操作者和证据。
元数据与证据字段来源、责任人、单位、语言、有效期、更新时间、证明文件、审核状态、数据版本字段级内部治理数据；不应因页面公开而一并公开。

字段治理要求

  • 每个字段具有稳定的字段 ID、数据类型、单位、枚举、必填条件、访问级别和法规映射。
  • 关键声明需记录数据提供方、佐证材料、审核人/时间、适用型号/批次和有效期；支持过期提醒与重新认证。
  • 护照公开信息应有“当前有效版本”；历史版本仅向有授权的内部/监管角色开放或按合规策略留存。
  • 对于暂未明确的附件 XIII 细项，使用配置式字段字典，不将待核验字段写死在产品代码中。

06 · 方案架构建议

1. 供应链数据工作台

品牌方、制造商、供应商按型号/批次填报；支持模板导入、API 接入、字段负责人、材料证据、补齐与退回。

2. 合规规则与质量引擎

规则版本化配置适用性、必填字段、数据格式、阈值及发布条件；法规升级后可回溯受影响型号。

3. 护照与身份服务

管理型号档案和单体唯一 ID；生成稳定二维码/短链解析入口；二维码只放访问入口和标识，不暴露敏感内容。

4. 访问与公开展示服务

公开护照页面、受控数据 API、身份/机构核验、访问策略执行、同意与授权管理、访问审计。

5. 生命周期数据服务

接入 IoT/BMS 运行数据、服务工单及回收伙伴事件；保留来源、时间戳、质量标识、授权和版本。

6. 集成与导出

对接 Tuya IoT、品牌方 ERP/PLM、供应商系统、第三方护照或合规平台；开放标准 API、批量导入/导出和迁移能力。

建议的逻辑关系：组织/责任主体 → 电池型号 → 生产批次 → 单体电池（唯一 ID/二维码） → 关联设备/储能系统 → 生命周期事件与数据证据。一个设备可能关联多个电池模块；应允许电池替换、扩容、拆分与历史关系追踪。

07 · 关键业务流程

① 规则判定录入类别、容量、用途和投放市场，确定护照义务与规则版本。
② 数据建档创建型号/批次，供应链填报字段并上传依据材料。
③ 校验审核执行完整性/逻辑校验；责任主体审核、签发或退回补充。
④ 单体绑定生成/导入电池唯一 ID，关联型号、批次、设备并生成二维码。
⑤ 发布维护扫码访问护照；持续接收授权的运行与生命周期更新，形成审计版本。

异常与更正场景

  • 型号资料缺失或证据过期：禁止签发/发布，提示责任人和字段级缺口。
  • 电池换新或设备绑定变更：旧关系留档，更新当前绑定，不复用/改写历史单体 ID。
  • 二维码损坏或护照迁移：解析标识应可恢复/重定向；不可因更换承载标签导致护照丢失。
  • 法规字段更改：按法规版本评估受影响护照，创建任务、限期补齐并保留审计。
  • 发布后发现错误：允许授权责任人更正并标记版本/变更日期；不得静默覆盖重要声明。

08 · 权限、安全与隐私

访问层级用户示例控制原则
公开消费者、公众、扫码用户仅呈现法规要求的公开字段；页面无需登录但防止批量滥用；不展示家庭地址、精确位置、用户身份等个人信息。
合法利益 / 业务授权维修、再利用、再制造、回收等相关主体验证组织与用途；依据法规字段授权，限定范围、期限和对象；记录授权依据与访问。
监管/合格评定机构公告机构、市场监管等依法有权主体机构身份核验、正式授权与审计；支持按请求提供完整、机器可读数据。
企业内部品牌方、制造商、供应链与合规团队租户隔离、字段级角色、审批分离；供应商只能访问获授权型号/字段。
  • 公开与受控字段分区存储/服务；服务端实施授权，不能依赖前端隐藏。
  • 重要操作（字段修改、审核、发布、撤回、授权、数据导出）写入不可抵赖审计日志。
  • 个人数据与电池技术数据分开治理；明确数据处理协议、保存期限、跨境传输和删除/更正机制。
  • 二维码 URL 应长期稳定、可迁移；限制枚举式 ID，防止未授权批量探测。

09 · 分阶段实施建议

阶段交付能力退出条件
阶段 0：法规与业务确认产品分类和责任主体矩阵；法规字段清单与访问矩阵；数据源/证据清单；二维码和标识方案。欧盟合规/法务、产品、业务、研发共同签字确认范围和字段 owner。
阶段 1：MVP（型号数据 + 护照发布）组织与权限、型号数据填报、字段校验/审核、唯一标识/二维码、公开护照页、数据导出、版本及审计。试点电池完成从资料录入到扫码展示全链路；公开/受控信息验证通过。
阶段 2：单体数据与 IoT 接入单体序列号、设备绑定、BMS 运行数据接入、授权访问、缺失/异常数据处理。选定 SKU 的数据质量、权限和运行稳定性达到服务目标。
阶段 3：生命周期与生态互通维修/替换/再利用/再制造/回收事件、伙伴 API、跨平台数据迁移和更广泛的多语言支持。关键合作方可按权限读写数据并完成端到端互操作验证。

建议不要把 IoT 实时数据接入作为首期阻塞项；法规字段、数据责任链、受控访问和护照标识应优先跑通。

10 · MVP 验收标准

  1. 可配置电池类别、容量门槛、欧盟市场与生效日期，并记录判定规则版本和复核记录。
  2. 责任主体可创建型号档案、上传字段证据、提交审核；系统准确指出必填缺项、格式/单位错误和过期材料。
  3. 发布的护照有稳定唯一标识；二维码扫码能解析到匹配电池，不会展示另一型号/单体的数据。
  4. 匿名用户只能看到公开字段；未授权用户无法通过 API、页面参数或导出接口读取受控数据。
  5. 字段修改、审核、发布、授权及数据导出均可审计；能查询当前有效版本与历史变更。
  6. 能导出结构化、机器可读数据；有明确 schema 版本，导出数据可用于迁移到其他服务。
  7. 覆盖电池更换、二维码标签损坏/重印、护照更正、角色撤权、护照服务恢复等异常测试。
